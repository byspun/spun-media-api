### Manifest Registration

- **Embeds** (`cinesrc`, `moviespro`, `flixhq`) → `enabled: false` for now.
- **Streaming priority**: vidnest=1, castle=2, then framextv=3, cinejoy=4, playimdb=5, daratech=6. Daratech left untouched for both streaming and downloads.
- **Downloading**: daratech=1, mkissa=3, moviesdrive=3.
- **Anime**: ID-capable providers ranked above fuzzy-title matchers → kaa=1, anikage=2, anv=3, reanime=4, anikoto=5 (pure title match), animegg=6, anizone=7, mkissa=8, animeonsen=9.
- **`supportedIds` honesty**: each provider declares only the ID systems it actually consumes (anv=`["anilist"]`, anikoto=`[]`). No claiming MAL or AniList support that the code doesn't use.

### The "Guessed Endpoints" Failure

The first pass at the new provider modules used plausible-looking but made-up endpoints. The health check flagged them all as down — correctly. Re-ported every module from the actual ultrasrc source, adapting each to the `get<Name>Streams(input)` contract rather than approximating it.

### Health Isolation

My first instinct was to soften failing providers into a `degraded` status behind a "known quirks" allowlist. That was wrong and got reverted. The health check tests each provider **in isolation** on purpose — masking a failure as degraded means a broken provider hides behind a passing one in a fallback chain, and there's no way to tell which is actually down. The `PROVIDERS_WITH_KNOWN_QUIRKS` set and its degraded branches were removed entirely. A red status now means genuinely broken.

| `providers/internal/data-literal.ts` | Safe parser for SvelteKit SSR object literals (no `eval`, null-prototype objects, depth/node limits). Used by FlixCloud. |

## Bugs Found & Fixed During Verification

| Bug | Root cause | Fix |
|---|---|---|
| `require is not defined` (reanime) | `internal/flixcloud.ts` used `require('node:worker_threads')` but the package is pure ESM | Top-level `import { Worker } from 'node:worker_threads'` |
| CineJoy gateway HTTP 400 | Sealed payload was **flattened**; upstream nests `{ path, mediaType, payload }` | Matched the nested shape |
| CineJoy type errors | tsconfig has no DOM lib — `WebAssembly`/`BufferSource`/`BodyInit` undeclared | Minimal structural typings (`WasmGlobal`, `WebAssemblyMemory`) |
| VidNest decryption always failed | **Wrong secret** hardcoded (`6d9b7e4f…` instead of the real `K3p8vQ2m…`) | Corrected to the real player-bundle secret |
| FlixCloud `BufferSource` casts | No DOM lib | Cast as `Buffer` instead |
| Unused `attachedSubtitles` import in vidnest | Leftover | Removed |

`★ Insight ─────────────────────────────────────`
- The CineJoy 400 was silent data loss: `boundedFetch` discarded the error body, so the only signal was a bare status code. Logging a prefix of the response body makes opaque gateway shapes debuggable.
- The VidNest secret bug type-checked and ran clean, returning `[]` — indistinguishable from "no streams available" unless the smoke test asserts on non-empty results.
- Referer-gated hosts (e.g. `fetch.nexabloom.top` → `https://megaplay.buzz/`) are handled inside the provider. Never set referers at the normalizer level — carry `headers` on the stream object.
