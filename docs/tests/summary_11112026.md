## 3. Manifest.json — Single Source of Truth

### Design Principles
- **Declarative**: Providers register via manifest only; modules on disk but not in manifest are never loaded
- **Explicit**: Every field is documented with JSONC comments explaining purpose and constraints
- **Conflict Detection**: Startup validates no two enabled providers share the same priority for the same (mediaType, capability)
- **Selective Skipping**: Conflicts skip only the conflicting operation, not the entire provider

### Schema (per entry)
```json
{
  "name": "provider_name",              // Must match exported function name
  "module": "./provider_name.ts",       // Relative to manifest
  "enabled": true,                      // false = registered but unused
  "type": ["movies", "series", "anime"], // Media types served
  "capabilities": ["streaming", "downloading"], // Operations supported
  "supportedIds": ["tmdb", "imdb", "anilist", "mal", "moviebox"], // ID systems usable
  "priority_stream": 1,                 // Optional; lower = tried first
  "priority_download": 1                // Optional; lower = tried first
}
```

## 4. Dynamic Provider Registry (`index.ts`)

### Core Components

#### `ProviderRegistry` Class
- **Manifest-Driven**: Reads `manifest.json` at startup, builds dispatch tables
- **Dynamic Module Loading**: Uses `import()` with caching; resolves `.ts`→`.js` via `resolveModuleSpecifier()`
- **Deferred Conflict Resolution**: Detects priority collisions per `(mediaType, capability)` at registration; logs warnings and skips only conflicting operations
- **Capability-Aware**: Separate fallback chains for `streaming` and `downloading`
- **Id-Gating Preserved**: Providers receive `spun_id` + original query; metadata layer owns ID mapping

#### Fallback Logic
```typescript
async function resolveWithFallback(
  providers: ProviderEntry[],
  capability: 'streaming' | 'downloading',
  query: any
): Promise<Result> {
  // Sort by priority ascending
  // Try each until one returns non-empty results
  // Track request-time health (3 failures/60s = suppressed)
}
```

#### Exported Resolution Functions
- `streamFor(query)` → `{ streams[], subtitles[] }`
- `downloadsFor(query)` → `{ downloads[], subtitles[] }`
- Registered with `HealthMonitor` for background checks

#### API Endpoints
| Endpoint | Method | Description |
|----------|--------|-------------|
| `/health` | GET | Overall + per-provider health (see Section 6) |
| `/streams` | GET | Streaming resolution with fallback |
| `/downloads` | GET | Download resolution with fallback |
| `/ready` | GET | Readiness probe (manifest loaded, registry built) |

## 6. Health Endpoint Upgrade

### Two-Layer Health System

#### Layer 1: Request-Time Tracking (Existing, Extended)
- Tracks consecutive failures per `(provider, category)`
- Suppresses provider after **3 failures in 60 seconds**
- Statuses: `healthy` | `degraded` | `down`
- Exported: `recordSuccess()`, `recordFailure()`, `isHealthy()`, `getHealthRecords()`

#### Layer 2: Background Health Monitoring (New)
- **Class**: `HealthMonitor` in `providers/internal/health.ts`
- **Test Fixtures** (hardcoded per media type):
  - **Movie**: Inception (2010) — TMDB: 27205, IMDB: tt1375666
  - **Series**: Breaking Bad S1E1 (2008) — TMDB: 1396, IMDB: tt0903747
  - **Anime**: Attack on Titan Ep 1 (2013) — AniList: 16498
- **Schedule**: Runs at startup + every 3 hours (10,800,000 ms)
- **Timeout**: 30 seconds per provider (isolated via `Promise.race`)
- **Error Classification**:
  - `timeout` / `429` / `rate limit` / `ECONNREFUSED` / `ENOTFOUND` → `degraded`
  - Other errors → `down`
- **Statuses**: `healthy` | `degraded` | `down` | `unknown`

## 7. Key Technical Decisions & Fixes

### Module Resolution Fix
**Problem**: Manifest references `.ts` files but dist output is `.js`
**Solution**: `resolveModuleSpecifier()` in `index.ts`:
```typescript
function resolveModuleSpecifier(specifier: string): string {
  const isDev = import.meta.url.endsWith('.ts');
  if (isDev) return specifier;
  return specifier.replace(/\.ts$/, '.js');
}
```

### Manifest Path Resolution
**Problem**: `health.ts` couldn't find `manifest.json` in both dev and dist
**Solution**: Used `import.meta.url` with `fileURLToPath(new URL('../../manifest.json', import.meta.url))`

### Health Monitor Manifest Loading
**Problem**: `HealthMonitor` constructor ran before manifest path was correct
**Solution**: Lazy-load in `getHealthCheckTargets()` with proper path resolution

### Provider Export Validation
**Problem**: `moviebox` declared `downloading` capability but didn't export `getMovieboxDownloads`
**Result**: Registry logs warning and skips moviebox for downloading only (streaming still works)

### Write Tool Corruption (Large Files)
**Issue**: Write tool corrupted files >~2000 lines
**Workaround**: Used Bash heredoc (`cat > file << 'EOF' ... EOF`) for large file creation

## 13. Dual Proxy Architecture (Designed, Not Yet Implemented)

### Context
- **Provider Layer** (Fastify on Render): Limited/expensive bandwidth
- **Metadata Layer** (Cloudflare Worker): Generous included bandwidth
- **Goal**: Single env switch (`ENABLE_PROXY`) controls both; metadata delegates to provider when both enabled

### Architecture

| `ENABLE_PROXY` | Provider Layer (`providers/internal/proxy.ts`) | Metadata Layer (`metadata/src/proxy.ts`) | Behavior |
|----------------|-----------------------------------------------|------------------------------------------|----------|
| `false` (default) | **Disabled** — returns 403 | **Enabled** — proxies all referer-gated streams | **Production today** |
| `true` | **Enabled** — fetches with injected headers | **Enabled** — delegates to provider if healthy | Self-hosted / internal deployment |

### Flow When Both Enabled
```
Client → Metadata (/v1/stream/...)
         │
         ├── shouldProxyStream(url) = NO → Return raw URL (direct play)
         │
         └── shouldProxyStream(url) = YES
                 │
                 ├── Provider layer healthy? → Delegate to Provider proxy
                 │     Returns: provider.internal/proxy/stream?url=...&referer=...
                 │
                 └── Provider layer down? → Fallback to Metadata proxy (/v1/proxy/stream?t=...)
```

### Provider-Layer Proxy (`providers/internal/proxy.ts`)
- Only loads if `ENABLE_PROXY=true`
- `GET /proxy/stream?url=...&referer=...&origin=...`
- Validates `url` against **manifest referer allowlist** (prevents open proxy abuse)
- Fetches with injected `Referer`, `Origin`, `Range` headers
- Pipes response with proper `Content-Type`, `Accept-Ranges`, CORS

### Metadata-Layer Delegation Logic
- Extends existing `shouldProxyStream()` in `metadata/src/routes/stream.ts`
- Reads `ENABLE_PROXY` and provider health from `/health` endpoint
- If delegation: returns signed provider-layer proxy URL instead of own `/v1/proxy/stream?t=...`
- Auto-fallback if provider layer reports `down`/`degraded`
