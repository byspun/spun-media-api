## Core Architecture Changes

### 1. Manifest-Driven Provider Registry (`providers/index.ts`)
- **Single source of truth**: `manifest.json` defines all providers, their types, capabilities, supported ID systems, and fallback priorities
- **Dynamic module loading**: Uses `import()` with caching; modules on disk are inert until registered in manifest
- **Priority-based fallback**: Lower priority number = tried first; per (mediaType, capability) combination
- **Conflict detection**: At startup, detects duplicate priorities for same mediaType+capability, logs warning, skips ALL providers in that conflict for that operation only
- **Selective skipping**: Conflicts don't disable providers for other capabilities/media types

### 2. Health Monitoring System (`providers/internal/health.ts`)
- **Background health checks**: Runs at startup + every 3 hours (10,800,000 ms interval)
- **Test fixtures** (hardcoded):
  - Movie: Inception (TMDB 27205, IMDB tt1375666)
  - TV: Breaking Bad S1E1 (TMDB 1396, IMDB tt0903747)
  - Anime: Attack on Titan Ep 1 (AniList 16498, MAL 16498)
- **Per-provider isolation**: Each provider tested independently with 30s timeout, error isolation (one failure doesn't affect others)
- **Status classification**:
  - `healthy`: Valid HTTP stream/download URL returned
  - `degraded`: Timeout, rate limit (429), connection errors
  - `down`: No valid URL, other errors
  - `unknown`: Never checked
- **Scheduler**: Uses `setInterval` with `unref()` to not block process exit

### 3. `/health` Endpoint (`GET /health`)
Returns comprehensive JSON:
```json
{
  "status": "healthy|degraded|down|unknown",
  "summary": { "healthy": N, "degraded": N, "down": N, "unknown": N },
  "providers": {
    "providerName": { "status": "...", "response_time": "XXXms" }
  }
}
```

### 4. Two-Layer Health Tracking
- **Request-time** (existing): Tracks consecutive failures per (provider, category), suppresses after 3 failures in 60s
- **Background monitoring** (new): Actual resolution requests against test fixtures, produces endpoint data

## Logging Improvements

### Core Logger (`core/logs/logger.ts`)
- **Deduplication**: 10-second sliding window
  - 1st occurrence: logged normally
  - 2nd occurrence: `×2 duplicate: <message>`
  - 3rd+: suppressed entirely (console only)
  - File logs: NOT deduplicated (complete audit trail)
- **Clean format**: `omitService: true` removes `[providers]` prefix
- **Redaction**: Strips auth headers, keys, tokens from URLs

### Provider Logger (`providers/internal/logging.ts`)
- File rotation daily (`YYYY-MM-DD.log`)
- Archive upload every 15 min (configurable via `LOG_UPLOAD_INTERVAL_MS`)
- Uses `createLogger({ omitService: true, onLine: writeLine })`

## How to Add a New Provider

1. **Create module**: `./newprovider.ts` exporting:
   - Streaming: `getNewproviderStreams(input, config) → Promise<RawStream[]>`
   - Downloading: `getNewproviderDownloads(input, config) → Promise<RawDownload[]>`

2. **Add to manifest.json**:
   ```json
   {
     "name": "newprovider",
     "module": "./newprovider.ts",
     "enabled": true,
     "type": ["anime"],           // or ["movies"], ["series"]
     "capabilities": ["streaming"], // or ["downloading"]
     "supportedIds": ["anilist", "mal"], // or ["tmdb"], ["moviebox"], []
     "priority_stream": 10
   }
   ```

3. **Restart service** (or wait ≤3 hours for next scheduled health check)

The health checker automatically:
- Picks appropriate fixture (anime → Attack on Titan)
- Passes both `anilist_id` and `mal_id`
- Validates against `supportedIds`
- Tests in isolation with 30s timeout
